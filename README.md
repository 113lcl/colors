# Undertow

Тёмное исследуемое пространство: сцена-мандала на входе, из которой пять кистевых
меток ведут в пять цветовых веток настроения. У каждой ветки четыре комнаты со своим
ощущением. Ничего не нужно проходить и не нужно выигрывать — только идти дальше,
пока идётся.

Ни бэкенда, ни базы, ни аккаунтов. Две комнаты помнят посетителя через `localStorage`
его же браузера, и это вся «память» проекта.

---

## Запуск

```bash
npm install
npm run dev
```

Дев-сервер поднимется на `http://localhost:4321`.

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер с горячей перезагрузкой |
| `npm run build` | собрать статику в `dist/` |
| `npm run preview` | посмотреть собранное локально |
| `npm test` | e2e: desktop, mobile, reduced-motion, без скриптов |
| `npm run crawl` | краулер связности по `dist/` |
| `npm run check-all` | сборка → краулер → e2e одной командой |

Перед первым `npm test` нужно один раз поставить браузер:

```bash
npx playwright install chromium
```

## Деплой

На выходе — обычная статика в `dist/`, без серверной части. Подойдёт любой статический
хостинг: Netlify, Vercel, Cloudflare Pages, GitHub Pages, S3.

В репозитории лежит `.github/workflows/deploy.yml`: он собирает сайт, прогоняет
краулер и тесты и публикует результат на GitHub Pages при пуше в `main`. Чтобы
заработало, в настройках репозитория нужно включить
**Settings → Pages → Source: GitHub Actions**.

### Если сайт лежит не в корне домена

GitHub Pages отдаёт проектный сайт по адресу `https://<аккаунт>.github.io/<репозиторий>/`.
Ссылка вида `/white/cloud/` там ведёт в никуда, поэтому префикс задаётся переменной
окружения при сборке:

```bash
SITE_BASE=colors npm run build
```

Все внутренние ссылки строятся через `src/lib/link.js`, который читает префикс у
Astro, — руками адреса нигде не собираются. Краулер понимает ту же переменную, так
что связность можно проверить ровно на тех адресах, по которым сайт будет жить:

```bash
SITE_BASE=colors npm run build && SITE_BASE=colors npm run crawl
```

Workflow делает это сам, подставляя имя репозитория. Для хостинга в корне домена
(Netlify, Vercel, Cloudflare Pages, свой домен) переменная не нужна.

## Как устроено

```
src/
  data/rooms.js          карта сайта — единственный источник правды
  layouts/Base.astro     шрифты, зерно, виньетка, тушевая пелена
  layouts/Room.astro     оболочка комнаты: шапка, выходы, метка визита
  components/            кистевые метки, блок выходов
  styles/tokens.css      цвета и шрифты из дизайн-системы
  styles/motion.css      пять грамматик движения
  styles/ink.css         переход между комнатами
  scripts/techniques/    библиотека интерактивных приёмов
  pages/<ветка>/<комната>.astro
scripts/crawl.mjs        проверка связности
tests/                   e2e и доступность
screenshots/             кадры (см. ниже)
```

Кадры в `screenshots/` пересобираются вместе с тестами, руками их обновлять не
нужно. Кроме портрета каждой комнаты там лежат кадры того, что в статике не
увидеть: `переход-тушь` — вспышка посреди перехода, `нарастание-*` — ветка в
начале блуждания и после того, как пройдены все её комнаты, `покой-*` — как
выглядят комнаты при `prefers-reduced-motion`, `мобильный-*` — узкий экран,
`00-центр-собирается` — сборка мандалы при первом приходе.

### Карта

Менять структуру сайта нужно в `src/data/rooms.js`. Оттуда её читают страницы, блок
выходов, краулер и тесты — в двадцати местах руками править ничего не надо.

### Грамматики движения

У каждой ветки свой характер движения, заданный переменными на `[data-branch]`
в `src/styles/motion.css`:

| Ветка | Характер | Микро | Состояние |
|---|---|---|---|
| Белая | плавно, без пружин | 380 ms | 780 ms |
| Зелёная | мягкая пружина с перелётом | 330 ms | 640 ms |
| Синяя | медленный дрейф, почти линейно | 420 ms | 2400 ms |
| Чёрная | намеренно неровно, с заминками | 230 ms | 540 ms |
| Красная | коротко и резко, с акцентом | 165 ms | 230 ms |

Комнаты берут тайминги только отсюда (`var(--ease-micro)`, `var(--dur-state)` и так
далее) и никогда не пишут `ease` или `linear` напрямую. Анимируются исключительно
`transform` и `opacity`.

### Библиотека приёмов

Шесть механик в `src/scripts/techniques/`, переиспользуемых во всех комнатах с разным
«скином» под настроение ветки. У каждой в шапке файла — однострочный пример.

1. `cursorSpot` — пятно за курсором с инерцией
2. `magnetic` — притяжение элемента к курсору
3. `revealText` — текст, проявляющийся в своём темпе
4. `dwell` — реакция на удержание, а не на клик
5. `scrollDrive` — прокрутка как единственный ввод
6. `toggleScene` — переключатель «до / после»

Плюс `accumulate` / `sinceLastVisit` — память между визитами для зелёной ветки.

### Что проверяется

`npm test` — это не «страница открылась без ошибок». Набор разложен по смыслу:

| Файл | Про что |
|---|---|
| `smoke` | страницы отвечают, выходы на месте, по комнате можно пройти клавиатурой |
| `interactions` | приём каждой комнаты действительно срабатывает |
| `motion` | грамматики движения, запрет браузерных таймингов, только transform и opacity |
| `reduced-motion` | ничего не движется, но ничего и не пропало |
| `mobile` | никакой горизонтальной прокрутки, выходы в кадре и под палец |
| `no-js` | без скриптов текст виден и ссылки работают |
| `a11y` | axe на каждой странице |
| `performance` | бюджет веса и скорость первой отрисовки |
| `screenshots` | по кадру с каждой комнаты плюс переход, нарастание и состояния покоя |

### Доступность

- `prefers-reduced-motion` решён глобально: анимация не обрывается, а замирает в
  середине своего цикла (`animation-play-state: paused` плюс отрицательная задержка).
  Комната при этом остаётся комнатой — это проверяется тестом на всех страницах.
  Важная тонкость: у одноразовых «появлений» смещение задано ЗА конец анимации,
  иначе элемент замирает в нулевой фазе, то есть прозрачным навсегда. Именно так
  однажды пропали выходы из комнаты.
- Сайт не разваливается без JavaScript: текст остаётся на месте, ссылки ведут
  обычной навигацией, пропадает только тушевый переход и интерактив.
- Все интерактивные элементы достижимы с клавиатуры; удержание в `dwell` работает и
  по фокусу, а не только по курсору.
- Тексты, которые визуально проявляются по словам, отдаются скринридеру целиком и
  сразу.
- Вспышка в красной ветке защищена паузой в 620 мс: частые клики не превращают её
  в стробоскоп.
- `npm test` включает прогон `@axe-core/playwright` по каждой странице.
