# Undertow — инструкция для ночной автономной сборки

Это самодостаточный бриф. Пиши так, будто читатель (в том числе будущий "ты" в следующем
цикле пробуждения) не видел разговор, из которого это родилось — вся нужная информация есть
здесь.

## Репозиторий

GitHub: **https://github.com/113lcl/colors**

Это рабочий репозиторий проекта. Первым делом — склонировать/инициализировать в нём проект
(если он пустой — `git init` локально и `git remote add origin` на этот адрес, либо

законченного и протестированного куска, не копить изменения надолго: это единственная
защита от потери прогресса, если что-то пойдёт не так с локальной средой за ночь.

## 0. Что это

Undertow — не сайт-визитка и не игра, а исследуемое пространство: тёмная сцена-мандала на
входе, из которой пять "чернильных" точек ведут в пять цветовых веток настроения. У каждой
ветки — 4 комнаты со своим ощущением. Ничего не нужно "выигрывать", нет геймификации, нет
аккаунтов, нет базы данных. Цель — чтобы было интересно бродить: одна комната доставляет
удовольствие, ведёт к следующей, та — к следующей.

Тон: утончённо, сдержанно, с лёгким японским акцентом (кисть, тушь, энсо, пустота "ma"),
универсально по аудитории, НЕ молодёжно-игриво, НЕ геймифицировано, НЕ "космос".

## 1. Дизайн-система (уже утверждена, не изобретай заново)

### Цвета
```
--ground:   #100e0c   /* фон сцены, тёплый почти-чёрный */
--ground-2: #17130f
--ink:      #e4ddcf   /* основной текст/линии */
--ink-dim:  #83786a   /* второстепенный текст */
--hair:     rgba(228,221,207,0.09)  /* тончайшие линии-разделители */

--c-black:  #6e5d7c   /* чёрная ветка — сливовый (специально светлее "чёрного",
                          иначе не виден на тёмном фоне — это уже проверено) */
--c-white:  #ece4d3   /* белая ветка — тёплая слоновая кость */
--c-green:  #66815a   /* зелёная ветка — насыщенный мох, НЕ бледный */
--c-red:    #a5544a   /* красная ветка — обожжённая охра-кирпич */
--c-blue:   #5c7a91   /* синяя ветка — пыльный индиго */
```
Сайт — единый нарочно тёмный мир (не переключатель светлой/тёмной темы). Не трать время на
светлую тему — это осознанный выбор, а не недосмотр.

### Типографика
- Display/акценты/подписи: **Shippori Mincho** (Google Fonts) — японский минчо-засечка.
- Основной текст/UI: **Archivo** (Google Fonts).
- Без Inter, без "безопасных" AI-дефолтов. Uppercase-лейблы — с небольшим трекингом.

### Референс лендинга
Приложен файл `undertow-landing-reference.html` — это одобренное решение первого экрана:
тёмная сцена, тихая точка-осознанность в центре, дыхательные кольца-рябь от неё, вокруг —
пять кистевых меток (реальная японская кисть, не CSS-градиенты и не неоновые шары — это
специально, после нескольких неудачных попыток с "шариками" и "космосом", которые были
явно отвергнуты). Возьми это за основу главной страницы, просто подключи реальные ссылки
вместо заглушек.

### Чему НЕ следовать (проверено на практике, не наступай на те же грабли)
- Никаких светящихся неоновых шаров/сфер с глянцевым бликом — читается как дешёвая 3D-модель.
- Никакого "звёздного неба"/разбросанных точек в темноте — читается как космос, это не нужно.
- Никакой мультяшности/игровой эстетики.
- Никакой геймификации (очки, ачивки, прогресс-бары "уровня").
- Никакого явного меню/навигационной панели — вход в комнаты только через встроенные в
  композицию точки/детали.

### Библиотека простых приёмов (переиспользуй, не изобретай сложную "игрушку" на каждую комнату)
Прошлый похожий проект провалился тем, что в каждой комнате пытались сделать отдельную
игрушку — получалось сыро. В этот раз: 5-6 простых интерактивных приёмов, доведённых до
блеска, переиспользуются во всех комнатах с разным "скином" под настроение ветки:
1. **Курсор-пятно** — мягкое пятно/блик следует за курсором с инерцией (lerp/spring).
2. **Магнитное притяжение** — элемент слегка тянется к курсору при приближении.
3. **Текст в своём темпе** — проявляется по буквам/словам с неравномерной скоростью.
4. **Реакция на удержание** — что-то происходит только если задержать курсор/палец дольше
   секунды (не мгновенно по клику).
5. **Скролл как единственный ввод** — элементы реагируют только на прокрутку.
6. **Переключатель "до/после"** — один клик меняет всю сцену на противоположную.

Примерно **40% комнат интерактивны** (используют один из приёмов), **60% чисто атмосферные**
(без ввода от пользователя). Распредели интерактив равномерно по всем пяти веткам (не
концентрируй в одной).

## 2. Анимации — это критично, отнестись максимально серьёзно

Весь смысл проекта держится на том, как всё двигается — не на количестве страниц. Прошлый
похожий проект был слабым именно из-за небрежной анимации (дефолтные тайминги, дёрганое
движение, ощущение "демки", а не готового продукта). В этот раз это не второстепенная
полировка в конце, а требование к каждому кусочку движения с самого начала.

Правила, обязательные для всего сайта:
- **Никогда не использовать дефолтный `ease`/`linear`/`ease-in-out` браузера бездумно.**
  Каждый переход — осознанно подобранная кривая (`cubic-bezier(...)`), под настроение
  конкретной ветки (см. ниже). Дефолтные тайминги CSS — самый быстрый способ, чтобы всё
  ощущалось дёшево.
- **Анимировать только `transform` и `opacity`.** Никогда не анимировать `top/left/width/
  height/margin` напрямую — это дёргается и режет производительность. Позиция/масштаб —
  через `translate`/`scale`.
- **Диапазоны длительности**: микро-реакции (наведение, клик) — 150–400ms; переходы между
  состояниями внутри комнаты — 400–800ms; атмосферные зацикленные движения — 4–20 секунд
  (чем медленнее и незаметнее, тем часто лучше — не должно бросаться в глаза, что это
  анимация вообще).
- **Разбивай синхронность.** Если на странице несколько одинаковых зацикленных анимаций —
  у каждой должны быть чуть разные длительность/задержка (`animation-delay`), иначе всё
  выглядит как одна механическая GIF-петля, а не живое пространство.
- **`prefers-reduced-motion: reduce`** — обязательно на КАЖДОЙ анимации без исключений.
  Не просто выключать анимацию резко — переводить в осмысленное статичное состояние покоя
  (то, каким элемент выглядел бы в середине своего цикла, а не в случайной точке).
- **У каждой ветки — своя "грамматика движения"**, одна и та же во всех её комнатах (это
  то, что делает ветку цельной, а не набором случайных страниц):
  - Белая — медленно, плавно, почти незаметный `ease`, без всякого "пружинения"
    (переходы 500ms+, кривая близкая к `ease-in-out`, никакого overshoot).
  - Чёрная — специально неровная: рваные, слегка асинхронные тайминги, микро-задержки,
    которые не совпадают с ожиданием (это единственная ветка, где "дёрганость" — фича,
    а не баг, но это должно ощущаться как что-то тонкое, не как лаг/баг лоадинга).
  - Зелёная — мягкая пружинистая кривая (лёгкий overshoot, `cubic-bezier` с небольшим
    "перелётом"), тёплое, отзывчивое движение.
  - Красная — короткие, резкие, быстрые переходы (150–250ms), чуть более выраженный
    overshoot/акцент — ощущение импульса.
  - Синяя — очень медленно, почти линейно, длинные переходы (несколько секунд), минимум
    "характера" в кривой — просто медленный дрейф.
- **Проверяй анимацию минимум на 2 циклах повтора**, прежде чем считать её готовой. Если на
  втором просмотре она ощущается как демо-заготовка из туториала, а не часть атмосферы —
  переделать тайминг/кривую, а не оставлять "и так сойдёт".
- Переходы между страницами (тушевая вспышка при переходе между комнатами) — единственная
  анимация, которая должна быть одинаковой по механике на всём сайте (меняется только цвет
  под ветку) — это то, что визуально скрепляет 20 разных комнат в один сайт.

## 3. Карта сайта и правила связности

Пять веток, у каждой свой характер и свой тип связи между комнатами:

| Ветка  | Ощущение                          | Связность                              | Реакции внутри комнаты |
|--------|-------------------------------------|-----------------------------------------|--------------------------|
| Белая  | спокойствие, забота                 | единое нарастающее путешествие          | **полностью предсказуемые** |
| Чёрная | неуют, тревога                      | единое нарастающее путешествие          | **намеренно непредсказуемые** (интерфейс "ведёт себя не так") |
| Зелёная| тепло, свежесть (без листьев/деревьев)| единое нарастающее путешествие        | предсказуемые, мягкие |
| Синяя  | меланхолия, дистанция                | единое нарастающее путешествие          | предсказуемые, медленные |
| Красная| напряжение                           | **независимые вспышки**, БЕЗ нарастания | предсказуемые в моменте, но резкие |

Навигация везде — **свободное блуждание без видимой карты/меню**. Каждая комната ведёт на
1–2 другие комнаты внутри своей ветки (граф связей внутри пятёрки комнат — на твой выбор,
лишь бы всё было достижимо и не было полных тупиков), плюс всегда есть тихий способ
вернуться к центральной мандале. Для веток-"путешествий" общее ощущение должно нарастать по
мере блуждания, но это не обязано быть жёстким линейным маршрутом.

### Белая ветка — комнаты
- **Облачный** — элемент медленно "выдыхает" (сжимается/расширяется), если задержать на нём
  курсор дольше секунды. *(интерактив: приём 4)*
- **Слоновая кость** — одна короткая фраза на весь экран, тающая и сменяющаяся другой по
  клику. *(интерактив: простой клик-переход)*
- **Морозный** — пустое пространство, где очень медленно проступают едва заметные линии,
  будто иней. *(атмосферная, без ввода)*
- **Песочный** — бесконечный плавный скролл одного простого повторяющегося узора, убаюкивает.
  *(интерактив: приём 5, скролл)*

### Чёрная ветка — комнаты
- **Антрацит** — курсор на странице слегка отстаёт от движения мыши или на миг раздваивается.
  *(интерактив: приём 1, но специально "сломанный"/задержанный)*
- **Баклажановый** — текст на странице каждый раз слегка переставлен местами при обновлении.
  *(атмосферная, генерируется при загрузке)*
- **Пепельный** — почти пустая комната, что-то едва заметно шевелится на периферии экрана
  боковым зрением. *(атмосферная)*
- **Оксблад** — обратный отсчёт без объяснений до чего, плюс резкий звук или внезапно
  обрывающаяся тишина. *(атмосферная; звук — опционально, если не успеваешь — тишина тоже
  работает)*

### Зелёная ветка — комнаты
- **Шалфейный** — абстрактная форма чуть "разрастается" с каждым повторным заходом на
  страницу (используй localStorage для счётчика визитов). *(интерактив: приём накопления)*
- **Мятный** — деталь мягко пружинит и "дышит" вслед за курсором. *(интерактив: приём 2)*
- **Тёплый оливковый** — показывает, сколько времени прошло с прошлого визита (localStorage
  timestamp), но подано тепло, как "давно не виделись", а не как тревожный таймер.
  *(атмосферная с лёгкой персонализацией)*
- **Жёлто-зелёный** — генеративный узор, каждый раз немного другой при перезагрузке (случайный
  seed). *(атмосферная)*

### Синяя ветка — комнаты
- **Глубокий** — текст очень медленно проявляется из темноты, чтение требует терпения.
  *(интерактив: приём 3, замедленный)*
- **Бирюзовый** — почти невесомое движение элементов, как отражения в воде (медленный
  параллакс от курсора или скролла). *(интерактив: приём 1 или 5, очень мягкий)*
- **Стальной** — абстрактный счётчик/визуализация огромного расстояния или времени, без
  конкретных единиц — просто ощущение масштаба. *(атмосферная)*
- **Сумеречный** — почти неподвижная сцена с очень медленным дрейфом мелких частиц.
  *(атмосферная)*

### Красная ветка — комнаты (независимые, без нарастания)
- **Оранжевый** — элемент пульсирует в ровном собственном ритме, лёгкое нетерпение.
  *(атмосферная, чистый ритм)*
- **Фиолетовый** — обратный отсчёт, который ускоряется, если задержаться на странице дольше.
  *(интерактив: приём 4, наоборот — задержка ускоряет, а не открывает)*
- **Розовый** — контраст формы и содержания: текст "кричит" крупным шрифтом, а по смыслу
  нежный или забавный. *(атмосферная, чисто типографическая)*
- **Жёлтый** — мягкая, но резкая вспышка при взаимодействии — на грани раздражителя, не
  дискомфортная. *(интерактив: приём клика/наведения)*

## 4. Технический стек

Никакого бэкенда, никакой базы данных, никаких аккаунтов — они не нужны для этой версии
(вся "память" — это localStorage на стороне клиента для пары персонализированных деталей
в зелёной ветке).

- **Astro** — статический сайт, файловая маршрутизация отлично ложится на структуру
  "ветка/комната", минимум лишнего JS на страницу.
- Чистый CSS (custom properties по токенам выше) — без Tailwind и подобного, чтобы сохранить
  авторский, не шаблонный визуал.
- Небольшие ванильные JS-модули на каждый интерактивный приём (общая переиспользуемая
  библиотека, см. раздел 1).
- **Playwright** — e2e: обход всех страниц, проверка отсутствия ошибок в консоли, проверка
  `prefers-reduced-motion`, проверка, что все внутренние ссылки резолвятся.
- **@axe-core/playwright** — базовая проверка доступности (контраст, aria, фокус).
- Простой скрипт-краулер, который проходит по всем внутренним ссылкам и репортит битые/
  недостижимые страницы.

## 5. Как работать всю ночь без остановки

Работай задачу за задачей по чек-листу ниже, без пауз на подтверждение — ты предполагаешься
никем не остановленным до утра. Конкретно:

1. После каждого законченного и протестированного куска — сразу коммит в git с понятным
   сообщением и `git push` в репозиторий выше. Не копи изменения надолго — если что-то
   сломается посреди ночи, важно, чтобы последний рабочий коммит был свежим.
2. Веди файл `PROGRESS.md` в корне репозитория — коротко после каждой значимой задачи: что
   сделано, прошли ли тесты, что не получилось и почему. Это единственный способ понять
   утром, что происходило ночью.
3. Веди `DECISIONS.md` — любое самостоятельное решение по неоднозначному моменту (точная
   формулировка фразы, конкретный оттенок, точный текст обратного отсчёта и т.п.). Никогда
   не останавливай работу ради уточнения — прими разумное решение в духе брифа, запиши его
   одной строкой в `DECISIONS.md` и иди дальше. Утром Тим пройдётся по этому списку разом.
4. Если задача оказалась крупнее, чем ожидалось — дроби её на более мелкие подкоммиты, а не
   держи всё в незакоммиченном виде до полного завершения.
5. Единственная причина реально остановиться и не продолжать — если что-то делает
   продолжение работы невозможным технически (например, окружение сломано и не
   восстанавливается). Во всех остальных случаях — предположение по умолчанию и заметка в
   `DECISIONS.md`, а не стоп.

## 6. Чек-лист задач по порядку

**0. Каркас.** Инициализировать Astro-проект, подключить шрифты, завести файл дизайн-токенов
(раздел 1), git init, настроить Playwright + axe, написать скрипт `run-all-checks`.
Готово = чистая сборка, пустой smoke-тест проходит.

**1. Общая система.** Реализовать переиспользуемые части: кистевые метки (SVG, как в
референсе), общий эффект перехода между страницами (тушевая "вспышка"/размытие в цвет
ветки — это должно ощущаться как фирменный приём сайта), пять "грамматик движения" по
веткам из раздела 2 (как переиспользуемые CSS-переменные с кривыми/длительностями),
защита `prefers-reduced-motion` везде, где есть анимация. Готово = временная служебная
страница показывает все части корректно, включая проверку каждой грамматики движения
(можно удалить перед финалом).

**2. Главная страница.** Адаптировать `undertow-landing-reference.html` в реальную домашнюю
страницу Astro, подключить настоящие ссылки на пять веток вместо заглушек. Готово = e2e
открывает главную, все пять меток на месте, доступны с клавиатуры (tabindex уже есть),
клик по каждой ведёт в нужную ветку.

**3. Библиотека интерактивных приёмов.** Реализовать 6 приёмов из раздела 1 как маленькие
переиспользуемые JS-модули, с однострочным примером использования в комментарии. Готово =
временная тестовая страница прогоняет каждый приём без ошибок (удалить перед финалом).

**4. Комнаты, по одной ветке за раз, в этом порядке: Белая → Зелёная → Синяя → Чёрная →
Красная.** (Начни с самых "предсказуемых", чтобы обкатать шаблон, самую капризную
чёрную — оставь на потом, когда паттерн уже проверен.) На каждую комнату: реализовать по
описанию из раздела 2, выбрать один приём (или ни одного — для атмосферных) в соответствии
с пропорцией 40/60, связать с 1–2 соседними комнатами той же ветки плюс тихий путь обратно
к центру. Готово на комнату = e2e открывает её без ошибок в консоли, уважает
reduced-motion, по ощущению соответствует своему описанию (самопроверка по брифу).

**5. Связность.** Прогнать краулер по всему сайту, починить недостижимые/тупиковые страницы,
убедиться, что каждая комната достижима от центра за разумное число переходов.

**6. Полировка.** Единый переходный эффект между всеми комнатами, проверка производительности
(Lighthouse, если доступен), проверка на мобильной ширине для каждой комнаты, отдельный
критический прогон именно чёрной ветки — тревога должна быть "на грани комфортной", не
отталкивающей (если сомневаешься — запиши как решение на утреннее подтверждение).

**7. Документация и сдача.** README (что это, как запустить локально, как задеплоить как
статику), папка со скриншотами (по одному на комнату — пригодится для портфолио), финальные
`PROGRESS.md` и `DECISIONS.md`.

## 7. Что не нужно делать

- Не строй бэкенд/базу данных/аккаунты — не требуется в этой версии.
- Не переключатель светлой/тёмной темы.
- Не игровая логика (победа/поражение/очки).
- Не завязывай контент буквально на цвета (никаких зелёных листьев в зелёной ветке и т.п.) —
  цвет = настроение, а не иллюстрация.
- Не оставляй анимации на дефолтных таймингах браузера "на потом" — см. раздел 2, это не
  полировка в конце, а требование с первого коммита.
